# Mambo 0.9.3 — проверка выпуска

Дата: 24 октября 2026 года.

## Подтверждено в текущей среде

- 45 настольных проверок: прежние сценарии Linux 0.9.2, темы и Noto Sans, таймер, повторные подключения, очистка процессов, диагностика, HTTP/TLS, новые сценарии навигации, пинг на странице серверов, сохранение его настроек, счётчики и обновление журнала.
- Дополнительный запуск проверки Engine: три реальных цикла VLESS → HTTPS, чтение счётчиков самого процесса, сброс при новом сеансе, сохранение итогов при остановке и запись в журнал.
- 8 проверок протоколов Python, включая 41 положительный/отрицательный WireGuard-профиль; те же 41 профиля приняты/отклонены Java-парсером.
- 39 Java-проверок импорта, HTTP/1.1, KeepAlive и конфигураций. Все 10 созданных Java-конфигураций приняты настоящим Xray.
- WireGuard: 8 локальных вариантов — IPv4/IPv6 × Python/Java × .conf/URI; HTTPS GET/HEAD, два запроса в одном TLS-соединении, DNS внутри туннеля, UDP-эхо, PSK и Reserved. Reserved проверен по передаваемым UDP-пакетам; неверный PSK не даёт успешного HTTPS-ответа.
- Итог расширенного WireGuard-стенда: 86 HTTPS-запросов и 20 DNS-запросов внутри туннеля. Дополнительно проверены новые диагностические DNS A/AAAA по SOCKS UDP, прямой HTTPS-путь и накопление дельт счётчика Java.
- Настоящие счётчики Xray проверены на локальном WireGuard-стенде: загрузка/выгрузка положительны, чтение не сбрасывает настольные значения. Java аккумулирует сбрасываемые JNI-счётчики ровно один раз в VPN-работнике.
- MTU 1280 попадает в настройки самого WireGuard outbound без изменения сохранённого профиля.
- Активный WireGuard используется повторно во всех режимах прокси-пинга; второй экземпляр с тем же ключом не создаётся. Другой WireGuard-профиль во время активного VPN проверять запрещено.
- Проверка Windows-портов: закрытое TCP-соединение и действующий слушатель различаются. Это автоматическая проверка Windows-ветки с моделированием ответов Winsock, не запуск на Windows.
- Оба APK компилируются целиком, проходят D8, zipalign и apksigner. Во всех APK находятся нужные нативные библиотеки. Выходной пакет — app.mambo.next.preview, versionCode 903, Android 10+.
- Настольный интерфейс запускался с Qt offscreen при 1180×820 и 900×680. Темы, отсутствие удалённого слогана, навигация и обновление элементов проверены автоматически; интерфейс также просмотрен по снимкам окна.

## Границы проверки

- Нет /dev/net/tun и необходимых системных разрешений. Полное системное подключение Linux не запускалось. sing-box принимает конфигурации; попытка запуска локальной sing-box-связки остановлена средой с operation not permitted. Локальный WireGuard проверен настоящим Xray без системного TUN.
- Windows EXE и Wintun не запускались в настоящей Windows; проверены комплектность архива, общий Python-код и Windows-конфигурации. Qt-интерфейс общий с Linux, но это не заменяет проверку на Windows.
- На физическом Android APK не запускались. Android VPNService, маршруты ОС, звук и внешний вид на конкретном телефоне здесь не проверены. JVM-тесты не равны тесту Android VPNService.
- Конкретный WireGuard-сервер пользователя и его сеть не проверены: конфигурация и журнал сбоя не приложены. Исправлены подтверждённые проблемы применения MTU и выбора Endpoint; гарантировать устранение неизвестной причины нельзя.
- Сравнение доступности и ошибки запросов не доказывают наличие DPI и не измеряют потери IP-пакетов. Прокси-проверки учитывают маршрутизацию. DNS-тест проверяет реальный UDP-ответ, а не только успешный connect() UDP-сокета.
- Счётчики — полезная нагрузка outbound proxy за сеанс, включая диагностические запросы. Прямой трафик и накладные расходы шифрования в эти значения не входят. При аварии процесса могут не сохраниться последние байты после последнего опроса.

## Android: отдельная подпись

В присланных исходниках нет прежнего ключа app.mambo.next. APK 0.9.3 имеют отдельный app.mambo.next.preview и новый ключ. Они ставятся рядом с основной версией, не обновляют её и не получают доступ к её данным. Исходное приложение удалять не нужно. Для обновления основного приложения с сохранением данных нужен его прежний ключ подписи.

Ключ Preview находится только в отдельном PRIVATE-Signing-Key архиве, исключён из исходников и пакетов остальных систем.

## Повторение проверок

Из корня проекта:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s protocol-tests -p test_protocols.py -v
python3 tools/verify_linux_packages.py --bundle linux --output dist
```

Сетевой стенд: `protocol-tests/network_matrix.py`. Ему нужны пути MAMBO_INPUTS/deps/core-linux/xray, MAMBO_INPUTS/deps/sing-box-linux/sing-box, скомпилированные Java test-classes и json.jar из Android-сборки. Режим без --relay проверяет Xray/WireGuard и не требует TUN; --relay дополнительно запускает sing-box и может потребовать недоступных в изолированной среде сетевых разрешений.

Исходники для сверки поведения: поставленные AndroidLibXrayLite v26.10.10 и Xray-core v26.10.10 в android/upstream. Описание параметров WireGuard: https://xtls.github.io/en/config/outbounds/wireguard.html .
